# 选品挖掘 · 需求信号工作台

这个项目不是"让 AI 直接告诉你什么品能卖",而是把跨境选品里最缺的一步补上:
**从海外真实用户表达里挖需求**。旧做法是看数据平台、看别人卖得好、再跟品;
这里的做法是先收集需求信号,再判断产品机会。

核心立场:**没有用户原话证据链的选品结论,一律不算数。**

## 30 秒跑通(零密钥零网络)

```bash
cd sct-camp
uv sync
uv run mining
```

浏览器自动打开工作台(`http://127.0.0.1:8708`),点「跑一遍 Demo」:
40 条自带的模拟用户表达(内容虚构,风格参考 Reddit 评论/Amazon 差评)几秒钟聚成痛点簇,
总览页直接看到机会点排序,「需求地图」页每个机会点都附 2-3 条用户原话证据。全程不用看终端。

CLI 子命令是同一条流水线的管线形态,给 AI agent 和自动化用:

```bash
uv run mining demo
```

产物(都在 `projects/product-mining/output/`,gitignored):

| 产物 | 说明 |
|---|---|
| `demo-report.html` | 一页需求地图:概览 + 机会点排序 + 每个机会点的用户原话证据 + 下一步验证清单 |
| `analysis.json` | 结构化信号提取结果(报告、工作台、AI 深挖都吃这一份) |

## 方法论:三源 → 需求信号 → 需求地图

```
① 收集用户表达(原话,不许改写)          ② 提取需求信号              ③ 需求地图
┌────────────────────────────┐
│ 评论:TikTok/短视频评论区    │       痛点聚类(效果/耐用/清洁/     机会点按
│   → 谁在问哪里买、吐槽什么   │  ──→  费力/伤材质/耗材/场景)  ──→  频次×情绪×来源
│ 差评:Amazon 1-3 星          │       + 情绪强度                   多样性排序,
│   → 现有产品哪里没做好       │       + 场景识别                   每个机会点带
│ 趋势:Google Trends + 论坛   │       + 来源交叉                   原话证据和
│   → 方向是否升温、长期痛点   │                                    微创新提示
└────────────────────────────┘
```

判断标准(哪些信号算真需求):

- **有用户原话**,优先级高;只来自卖家页面描述,优先级低。
- **多个来源交叉验证**(评论 + 差评都在骂同一件事),优先级高。
- **带情绪、带场景**("my arm is sore after one room"),比抽象抱怨值钱。
- 不能被供应链验证的创新点,暂时不要写成结论。
- 搜索结果数量不等于需求强弱;平台卖点不等于用户需求。

## 换成你自己的品类

1. 把 `input/keywords.example.md` 复制成 `input/keywords.md`,填品类、市场、种子词;
2. 自动采集(零密钥,标准库直连):

```bash
uv run mining fetch --keyword "pet hair remover" --limit 5   # Reddit 公开 JSON:帖子+高票评论
uv run mining fetch --asin B0XXXXXXXX                        # Amazon 差评(Woot JSON,先在商品页确认 ASIN)
```

3. 自动够不着的(TikTok 评论区、Quora、Google Trends),用最笨最稳的办法:
   人工打开页面,把扎心的用户原话以 `> 原话` 格式贴进 `input/` 对应模板;
4. 提取信号,生成需求地图:

```bash
uv run mining analyze        # expressions.jsonl + input/ 手贴原话 → demand-map.html
```

外部源偶发 403/429/超时是对方的风控脾气,不是项目坏了:稍后重跑,或先靠手贴材料跑 analyze。

## 怎么问 AI(比代码更重要)

规则聚类只能算粗账,深挖交给 AI。打开 Codex / Claude,别这样问:

> 帮我看看这个品能不能做。

要这样开局(先要计划,不要结论):

```text
你现在是跨境选品需求挖掘助手。我的品类方向是:__,目标市场是:__,目标用户是:__。
不要直接判断这个品能不能做。先给我一份需求挖掘计划:
1. 去哪几个地方找需求证据;2. 每个平台搜什么词(要能直接复制);
3. 复制哪些评论/帖子/差评;4. 哪些信号算真需求,哪些只是噪音。
```

材料收齐、跑完 analyze 之后,把 `output/analysis.json`(或需求地图 HTML)喂给 AI:

```text
这是我的需求信号提取结果。请基于它输出需求挖掘地图,要求:
1. 一句话定义这个品类解决什么问题;2. 用户画像:谁在痛、典型生活场景;
3. 高频痛点按证据强度排序;4. 用户原话证据,保留原文不要编;
5. 现有产品失败点(来自差评);6. 微创新方向,每个都必须对应一个真实痛点;
7. 内容机会:适合短视频的前后对比/反差/测试场景;8. 供应链验证清单;
9. 风险(平台/合规/专利/夸大宣传);10. 用最小成本验证的 3 个动作。
不要编数据,每个判断都要引用材料;不能被供应链验证的创新点不要写成结论。
```

痛点聚类用表格问法:痛点簇 | 用户原话证据 | 出现场景 | 现有方案为什么不够 | 可做的微创新 | 供应链验证 | 内容钩子。
不要把同义痛点拆成很多行,不要为了显得丰富而编新痛点,每个内容钩子要能拍成 15-60 秒短视频。

## 课堂作业标准

选一个你正在关注的品类,收齐再下结论:

- 至少 20 条 TikTok/短视频评论(手贴 `input/tiktok-comments.md`);
- 至少 5 个 Reddit/Quora/论坛讨论片段(fetch + 手贴);
- 至少 20 条 Amazon 低星差评(fetch --asin + 手贴);
- 至少 3 组 Google Trends 关键词对比(记进 `input/google-trends-notes.md`);
- 输出一份"这个品类为什么有人需要、现有产品哪里没做好、我能怎么微创新"的需求地图。

## 进阶:更多数据源(代码未迁,按需去源项目)

本项目刻意只保留纯 HTTP、零密钥的采集(Reddit 公开 JSON + Amazon Woot JSON),
数据量是几十条文本,标准库足够。以下重栈路径在源项目
`SCT-AI超级个体营/08-实践项目/选品挖掘/` 里有完整可跑版本,不迁进基座:

| 数据源 | 为什么不迁 | 源项目路径 / 稳定替代 |
|---|---|---|
| Google Trends | pytrends 非官方接口,易 429 限流,教学噪音大 | `scripts/google_trends_sample.py`;稳定走 SerpApi 或手动截图 |
| TikTok 标签页/评论 | 需要 Node + Playwright 或登录态,风控重 | `scripts/fetch_tiktok_tag_browser.js`;稳定走 ExportComments / EnsembleData / Apify |
| Reddit 全量 | PRAW 要 Reddit app credentials,公开 JSON 够课堂用 | `scripts/` + PRAW 文档 |
| Quora | Cloudflare 403,别硬爬 | 搜索定位 + 人工摘录进 `input/forum-notes.md` |
